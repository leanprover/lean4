### What still falls back to extern / untranslated

Everything outside the current MVP set is still effectively untranslated.
Measured against the `lean.h` inline surface, that leaves roughly
**539 inline helpers** not yet ported as Zig definitions.

Those remaining helpers are not all equally important; the main deferred
families are:

- additional box/unbox helpers not needed by the current smoke suite,
- broader array and scalar-array update helpers,
- much larger Nat/Int/UInt arithmetic families,
- string/UTF-8 helpers beyond the minimal smoke path,
- IO/task/debug/exception inline conveniences,
- compact-region, serialization, and advanced runtime helpers,
- helper families only reachable once EmitZig compiles more of the stdlib.

Today the smoke-covered programs succeed because all inline helpers they touch
have been translated. Outside that cone, a newly reached inline helper will
still appear as an unresolved coverage gap until it is either translated into
`InlineHelpers.lean` or replaced with a call to a real exported runtime symbol.

## Deferred LCNF cases and M9 promotion notes

The following items are intentionally deferred beyond M6:

1. **Closed-term / ground-value emission**
   - No `emitGroundDecl` equivalent exists yet.
   - M7 should add a shadow-tree implementation for stdlib-heavy modules.
   - M9 promotion should decide whether to mirror EmitC's constant-pool layout
     exactly or keep the simpler runtime-construction approach where possible.

2. **Full `cases` parity**
   - Constructor/predicate cases used by the smoke suite are covered.
   - Some pure-case paths still hit `@panic("EmitZig pure cases not implemented yet")`.
   - Before promotion, this should be eliminated so `EmitZig` is total over the
     same LCNF body space as EmitC.

3. **Multi-inc / multi-dec lowering**
   - Current code handles the common single-step RC paths.
   - Explicit multiplicity > 1 still lands in panic placeholders.
   - M7 should normalize or implement the multiplicity-aware forms directly.

4. **Opaque `@[extern]` declarations**
   - M6 handles the smoke-relevant standard and inline extern paths.
   - Generic opaque extern coverage is not yet trustworthy.
   - M9 promotion should line this up with EmitC's extern classification logic so
     the stage1 backend can consume the full compiler surface.

5. **Exception-aware emission**
   - The generated wrapper handles `lean_io_result_*` at the file boundary.
   - There is no broader exception lowering story yet.
   - M7/M9 should decide whether to stay close to EmitC's current operational
     contract or introduce Zig-native abstractions only behind exact ABI shims.

6. **Stage1 integration**
   - M6 deliberately lives in `zig-backend/src/EmitZig/`.
   - M9 must move the implementation into `src/Lean/Compiler/LCNF/EmitZig.lean`,
     wire it into the real compiler pipeline, and audit stage0/build-system fallout.

## Known limitations

### Panic emission gap

The current backend still contains explicit panic placeholders in unsupported
paths, including:

- missing EmitZig signatures for some functions,
- failed extern application fallback,
- multi-inc / multi-dec lowering,
- pure-case fallback inside some `cases` paths,
- generic "body emission not implemented yet" escape hatches.

That is acceptable for M6 because the covered smoke/test surface avoids those
paths, but it is not acceptable for broader stdlib compilation.

### Exception handling

M6 only covers the `lean_io_result_*` wrapper contract needed to run the smoke
programs. It does **not** implement a general exception/panic lowering strategy
matching the full upstream backend.

### Opaque externs

Opaque extern handling is still a known gap. The current implementation is good
enough for the smoke-relevant standard/inline extern paths, but not for the full
universe of `@[extern]` declarations that EmitC can route today.

### No closed-term pool emission yet

The backend currently succeeds by sticking to smoke programs that do not require
an `emitGroundDecl`-style constant-pool implementation. That will become a real
limitation as soon as the backend is asked to compile broader stdlib fragments.

## Next steps for M7

M7 should focus on widening the backend from "three smoke programs" to "enough
stdlib/compiler surface to make stage1-scale progress":

1. implement closed-term / ground-value emission,
2. remove all panic placeholders in reachable LCNF emission paths,
3. expand inline-helper translation coverage systematically instead of by
   smoke-driven hand selection,
4. finish opaque-extern coverage,
5. compile larger stdlib slices through the shadow-tree backend and add those as
   new reproducible smoke/differential fixtures,
6. keep the outer repo clean until the explicit M9 promotion step.

In short: M6 proved the shadow-tree approach, the wrapper/runtime contract, and
observable parity with EmitC for the MVP programs. M7 should turn that from a
smoke-tested prototype into a backend that can survive much larger real-world
LCNF workloads without falling back to panic stubs or missing helper coverage.
